## Docker Sandbox option

Assume the sandbox was created like this:

```text
sbx create --clone --name {sandboxName} codex .
```

Explain the key concept clearly:

- With `--clone`, the sandbox works in its own private clone of the repository.
- Changes made by Codex inside the sandbox may not directly appear in the normal Windows/local folder.
- The host repository should fetch and merge the sandbox work, then push the feature branch to GitHub.

Add a warning/note:

```text
Use this path when the agent changed files inside a Docker Sandbox created with `sbx create --clone`. First inspect the sandbox remote/branch, then merge the sandbox work onto your local feature branch, then push that feature branch to origin.
```

### Docker Sandbox command sequence

1. Inspect host repo state and remotes:

```text
git status
git remote -v
git branch --show-current
```

2. Fetch the sandbox remote:

```text
git fetch {sandboxName}
```

Explain that `{sandboxName}` may need to be replaced by the actual remote name shown by `git remote -v`.

3. Inspect sandbox branches/commits:

```text
git branch -a
git log --oneline --all --decorate --graph -20
```

Explain that common candidates are `{sandboxName}/main` or `{sandboxName}/{featureBranch}`.

4. Switch to the intended local feature branch:

```text
git switch {featureBranch}
```

Explain that sandbox changes should be merged into the feature branch, not directly into `{defaultBranch}`.

5. Merge sandbox work onto the feature branch:

Primary command:

```text
git merge {sandboxName}/main
```

Alternative if the sandbox work is on the feature branch:

```text
git merge {sandboxName}/{featureBranch}
```

Explain that the user should choose the remote branch visible in `git branch -a` / `git log`. If conflicts occur, stop and resolve them before continuing.

6. Inspect the merge result:

```text
git status
git diff --stat
```

7. Commit if the merge left local changes uncommitted:

```text
git add .
git commit -m "Integrate Docker Sandbox changes"
```

Explain that this step is skipped if Git already made a merge commit or says there is nothing to commit.

8. Push the feature branch to GitHub:

```text
git push -u origin {featureBranch}
```

End with a note:

```text
After this, continue with `III. Finish Clean`: create the pull request, merge it, and update the local default branch.
```
